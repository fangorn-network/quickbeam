================================================================================
JACKSON, MS — LOCAL DISCOVERY EMBEDDINGS RUNBOOK (from scratch)
================================================================================

Build a small, self-contained semantic-search shard for a locality (here:
Jackson, Mississippi) covering its physical BUSINESSES (Google Places: hours,
ratings, reviews) and the EVENTS happening at them (Eventbrite/Tribe), then
browse it in a local web UI.

This uses the LOCAL PREBAKE path (no blockchain / no Fangorn publishing). It is
the fastest way to a working demo. The on-chain `quickbeam build` path exists too
(see docs/LOCAL_DISCOVERY_GUIDE.md) but is not needed here.

Pipeline at a glance:
  scrape (Stage A)  ->  raw->graph (Stage B)  ->  schema+embed+bake (Stage C)  ->  demo (Stage D)
  Google Places +        placespg /                schemagen / prebake /             cdn serve +
  Eventbrite             eventspg                  cdn bake                          examples app

Only Stage A costs money. Everything downstream reprocesses the local cache for
free, so you can iterate the model and re-bake without re-paying Google.

Run everything from the repo root unless noted.

--------------------------------------------------------------------------------
PREREQUISITES
--------------------------------------------------------------------------------
- Docker (for Qdrant + Postgres)
- Python 3.12 + the repo venv  (developed on 3.12.3)
- Node 18+  (developed on Node 22) — for the demo UI in examples/
- A Google Cloud API key with "Places API (new)" enabled AND billing on.
  >> Do NOT paste your real key into this file or any committed file. Export it
     in your shell only. Treat a leaked key as compromised and rotate it.

Install the CLI once (from repo root):
  python -m venv venv
  source venv/bin/activate
  pip install -e ".[gpu]"     # CUDA build; or ".[cpu]" for CPU-only
  quickbeam --help

--------------------------------------------------------------------------------
STAGE A — SCRAPE JACKSON  (the ONLY step that costs money)
--------------------------------------------------------------------------------
Jackson, MS downtown center: 32.2988,-90.1848

There are TWO kinds of search and they behave differently:
  * Nearby Search (--location/--radius/--sweep)  -> FILTERED by --types, capped
    at 20 results per tile, ranked by Google's opaque "prominence".
  * Text Search (--query)                         -> IGNORES --types entirely;
    matches on name/relevance. This is how you catch niche, type-less places.

----- A1. Places: a wide sweep PLUS text passes (recommended for full coverage) -

# Wide, VALID Google type net (max 50 types per Nearby call). Adds the niche
# subtypes that actually exist in Google's Table A (book_store, gift_shop,
# thrift_store, art_gallery, museums, performing arts, etc.).
TYPES="restaurant,cafe,coffee_shop,bar,pub,wine_bar,bakery,ice_cream_shop,meal_takeaway,fast_food_restaurant,store,book_store,clothing_store,shoe_store,jewelry_store,gift_shop,thrift_store,electronics_store,furniture_store,home_goods_store,hardware_store,sporting_goods_store,pet_store,liquor_store,convenience_store,grocery_store,supermarket,department_store,shopping_mall,florist,art_gallery,museum,art_museum,history_museum,cultural_center,performing_arts_theater,concert_hall,movie_theater,night_club,tourist_attraction,hair_care,beauty_salon,barber_shop,spa,gym,park"

# ALWAYS dry-run first: runs only the free Search, reports billable Place Details
# a real run WOULD make. Fetches/stores nothing.
quickbeam data places-fetch --location 32.2988,-90.1848 --radius 12000 \
  --types "$TYPES" --sweep --min-radius 250 --max-tiles 600 --max-details 500 --dry-run

# Real run once the cost looks right. --max-details is your HARD spend ceiling.
quickbeam data places-fetch --location 32.2988,-90.1848 --radius 12000 \
  --types "$TYPES" --sweep --min-radius 250 --max-tiles 600 --max-details 500

# Text passes catch the long tail Google has NO type for (record/vinyl shops,
# antiques, tattoo, comic/hobby). Put the locality IN the query string.
for q in "record stores in Jackson MS" \
         "vintage and antique shops in Jackson MS" \
         "art galleries in Jackson MS" \
         "independent bookstores in Jackson MS" \
         "live music venues in Jackson MS"; do
  quickbeam data places-fetch --query "$q" --max-results 60
done

--------------------------------------------------------------------------------
STAGE C — SCHEMA + EMBEDDINGS + SHARD  (prebake path)
--------------------------------------------------------------------------------

# C1. Infer one bundle schema across BOTH volumes (--volume 0 = all volumes).
quickbeam data schemagen --input-dir ./stage_volumes --volume 0 \
  --prefix fangorn.places --bundle-name localcore --version v1

# C2. CREATE THE QDRANT COLLECTION FIRST.
# *** prebake does NOT create the collection — it only uploads into it. ***
# Must match the embedding recipe: size 256, Cosine, on_disk (this is exactly
# what `quickbeam build` creates). If you change --dim later, change size to match.
curl -X PUT http://localhost:6333/collections/fangorn \
  -H 'Content-Type: application/json' \
  -d '{"vectors": {"size": 256, "distance": "Cosine", "on_disk": true}}'

# C3. Embed BUSINESSES first (volume 1). They are the places themselves AND the
# targets that --link-events folds event titles into, so they must exist before C4.
quickbeam data prebake --input-dir ./stage_volumes --volume 1 --types Business --collection fangorn

# C4. Embed EVENTS + organizers (volume 2). --link-events folds each event's title
# into its venue's Business payload (payload-only; business vectors untouched).
# Skip this step entirely if you have no events.
quickbeam data prebake --input-dir ./stage_volumes --volume 2 \
  --types Event,Organizer --collection fangorn --link-events

# C5. Bake the static CDN shard. The "places" domain filter in domains.json keeps
# entityType in {Business, Event}; other node types are dropped from the shard.
quickbeam cdn bake --collection fangorn --domain places --cdn-dir ./cdn

--------------------------------------------------------------------------------
PITFALLS & GOTCHAS  (read this — it will save you an hour)
--------------------------------------------------------------------------------
1. prebake does NOT create the Qdrant collection. If the collection is missing
   you get: NOT_FOUND: Collection `fangorn` doesn't exist!  -> do Stage C2 first.
   (Its index-setup step swallows the same error and mislabels it "already
   present", so the real failure only shows up at the upload step.)

2. ORDER MATTERS in prebake: businesses (volume 1) BEFORE events (volume 2).
   The volume-2 --link-events step writes into EXISTING Business points; run it
   first and it has nothing to fold into. The guide's short example only shows the
   volume-2 command — that alone gives you an events-only collection with no places.

3. The CDN "places" domain filter keeps only entityType in {Business, Event}.
   Organizer/Review/Category/Reviewer/Locality points are dropped at bake time.
   Consequence of the PREBAKE path specifically: review text is NOT folded into
   business documents (that folding only happens in the on-chain `build`
   root-profiles path), so a review-only term ("tacos") may not surface its
   business. Businesses are still searchable by name, type, locality, editorial
   summary, rating, amenities.

4. --bbox with a leading negative longitude needs the "=" form:
   --bbox="-90.40,..."  (a space makes argparse treat the value as a flag).
   Same trick for any flag whose value starts with "-".

5. Eventbrite anti-bot: a 405 "Human Verification" HTML page means you were
   blocked, not that your command was wrong (it will report "Saved 0 events").
   Events are optional. Retry later / different network, try a Tribe site, or ship
   businesses-only and add events later.

6. Niche places & the type net:
   - --types ONLY filters the Nearby sweep. Text Search (--query) ignores it.
   - Google has NO record_store / vinyl / antique / tattoo / comic type — those
     collapse to the generic "store". So a wider type net will NOT catch a record
     shop; Text Search will. Use both.
   - Nearby Search is capped at 20 results per tile, ranked by "prominence", so
     low-prominence indie shops get dropped from dense tiles. --sweep subdivides
     a tile only when it returns exactly 20, and stops at --min-radius. Lower
     --min-radius (e.g. 250) and raise --max-tiles to dig deeper; raise
     --max-details so the run isn't truncated. Coverage reaching a block does NOT
     guarantee a given shop was returned.

7. CUDA/GPU is optional. If you see
   "libcudnn.so.9: cannot open shared object file" the embedder fell back to CPU —
   harmless for a few hundred nodes (finishes in seconds). To use the GPU:
     export LD_LIBRARY_PATH=$VIRTUAL_ENV/lib/python3.12/site-packages/nvidia/cudnn/lib:\
   $VIRTUAL_ENV/lib/python3.12/site-packages/nvidia/cublas/lib:$LD_LIBRARY_PATH
     python -c "import onnxruntime as ort; print(ort.get_available_providers())"

8. `cdn serve` MUST be started with --cors for the browser app (shards mode) to
   fetch shards cross-origin; without it the UI shows a connection-error badge.

9. Vite dev port: if 5173 is taken it silently moves to 5174 — use the URL it
   prints. The browser TAB TITLE is hardcoded to "Eagle River" in
   examples/index.html (static, not env-driven); the in-PAGE community name does
   honor VITE_COMMUNITY_*.

10. Localization: VITE_COMMUNITY_* overrides only the name/region labels. The
    "vibe" quick-searches and microcopy still come from VITE_LOCALE
    (default en-eagle-river — Northwoods flavor). For a true Jackson voice, copy
    examples/src/lib/i18n/en-eagle-river.ts to an en-jackson profile, translate
    the vibes/strings, register it in i18n/index.ts, and run with
    VITE_LOCALE=en-jackson.

11. cdn/ IS tracked in git (a fresh clone ships old music/places shards);
    stage_volumes/ and db/ are gitignored. Re-baking overwrites cdn/places.

12. The embedding model must match between embed and any later query path
    (nomic-ai/nomic-embed-text-v1.5, dim 256). Don't mix dims: the collection
    vector size, --dim at prebake, and the baked manifest must all agree.

--------------------------------------------------------------------------------
COST & BILLING SAFETY
--------------------------------------------------------------------------------
- FREE: all Search calls (Nearby + Text) use an IDs-only field mask = Google's
  "Essentials (IDs Only)" SKU, billed at no cost. A --sweep multiplies only these
  cheap calls.
- BILLABLE: Place Details, once per UNIQUE business (dedup by place_id), at the
  Enterprise + Atmosphere tier (full mask incl. reviews/ratings), ~$0.025 each
  (~$25 / 1,000) at list price. 60 businesses ~= $1.50; a full Jackson can be a
  few hundred (~$5-10 at list) — and is often $0 under Google's monthly free
  allotment for that tier.
- ALWAYS --dry-run first. --max-details is a per-run hard ceiling.
- The ONLY thing that truly stops spend: a per-day QUOTA CAP in Google Cloud ->
  APIs & Services -> Places API (new) -> Quotas. Over-limit calls are REJECTED,
  not billed. Budget alerts only notify.
- ToS: treat places_raw / events_raw as a short-lived prototype cache; store
  metadata only, don't redistribute raw review text.
